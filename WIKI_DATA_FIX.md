# BossWise data + gear-picker fix

Short version, three things:

1. The combat numbers in `equipment.json` and `monsters.json` were hand-typed and
   a lot of them were wrong. They now come from the wiki, by script.
2. The gear optimiser ranked items with a scoring heuristic instead of running
   your own DPS maths. It now measures.
3. New: look an account up by name through WikiSync, so BossWise can advise for
   an account this client is not logged into (section 5).

Everything below is reproducible — the sync script is in `tools/`.

## 1. Where the numbers come from now

Source: the Old School RuneScape Wiki's own DPS calculator dataset
(`https://github.com/weirdgloop/osrs-dps-calc`, `cdn/json/equipment.json` and
`cdn/json/monsters.json`), commit `74958b1`, 12 Nov 2026. That dataset is
generated straight from the wiki infoboxes, so it is the same numbers the wiki
pages show, for 5,000+ items and 3,000+ monsters.

Re-run it any time:

```bash
git clone --depth 1 https://github.com/weirdgloop/osrs-dps-calc.git ../osrs-dps-calc
python3 tools/sync_wiki_data.py . ../osrs-dps-calc
```

It rewrites only stats. Prices, tiers, quest/skill requirements, locations,
variant names, flags (dragonbane, demonbane, …), strategy text and mechanics are
left exactly as you wrote them.

## 2. What it corrected

- **171 of 223 items**, 723 individual fields.
- **All 87 monster variants**, 647 fields.
- Full line-by-line list in `DATA_SYNC_REPORT.txt` (generated by the script).

Examples of what was off:

| Thing | Was | Wiki |
|---|---|---|
| Rune crossbow attack speed | 4 ticks | 6 ticks |
| Zaryte crossbow / DHCB / ACB speed | 4 | 6 |
| Toxic blowpipe speed | 2 | 3 |
| Karil's crossbow speed | 3 | 4 |
| Leaf-bladed sword slash attack | 0 | 62 |
| Osmumten's fang-class stab weapons | many stab/slash bonuses at 0 | real values |
| Soulreaper axe slash / strength | 121 / 135 | 134 / 125 |
| Emberlight strength | 80 | 13 |
| King Black Dragon stab defence | 70 | 40 |
| Kree'arra ranged defence | 15 | 200 |
| Vorkath (post-quest) stab defence | 26 | 66 |
| Thermonuclear smoke devil defences | 120/80/100 | 11/4/9 |

Attack speed and defence errors matter most: they move DPS directly, and the
optimiser was choosing gear off them.

**Magic damage units:** the wiki dataset stores magic damage in tenths of a
percent (Kodai wand = 150 = +15%). The sync divides by 10, so
`magicDamagePercent` stays in whole percent like your calculator expects. Watch
that if you ever pull from the dataset by hand — the first pass here produced
193 max hits before I caught it.

**Item and NPC ids:** 21 item ids pointed at a *different item* (e.g. "Dragon
sword" was carrying the Dragon shortsword id, Keris partisan had Elidinis' ward's
id, Magus/Bellator/Ultor/Venator rings were shuffled, Monk's robe top and
bottom were swapped). Those are corrected and the old value is kept in
`legacyItemId`. Ids the wiki dataset simply doesn't model (it splits items by
charge state) were left alone so in-game detection keeps working — the script
lists those instead of changing them.

26 npcIds were wrong (Dagannoth Rex had Supreme's id, Spindel had a grizzly
bear's, Callisto/Venenatis had pre-rework ids, Grotesque Guardians' were off).
Fixed, with the old value in `legacyNpcId`.

## 3. New monster fields

Each variant now carries, straight from the wiki:

- `maxHit` — as the wiki writes it, e.g. `"25 (Melee)"`, `"27 / 28 / 29 (phase 4)"`, `"17x2 (default)"`.
- `attackStyles` — real styles, not just "Melee": `["Stab", "Dragonfire"]` for KBD,
  `["Magical melee"]` for Bloodveld, `["Magic (100% prayer penetration)"]` for Kraken.
- `attributes` — wiki monster types: `dragon`, `demon`, `undead`, `kalphite`,
  `leafy`, `golem`, `fiery`, `spectral`, `xerician`, `rat`. A monster can have
  several (Vorkath is `dragon, undead, fiery`), which the single `classification`
  field couldn't express. `classification` is still set for backwards
  compatibility, and filled in from the attributes where it was NONE.
- `wikiName` — exactly which wiki row the numbers came from, so a wrong match is
  obvious instead of silent.

`MonsterVariant` has `getMaxHit()`, `getAttributes()` and `hasAttribute("demon")`.
The old 20-arg constructor still works (it delegates), so nothing that builds a
variant by hand breaks. The boss guide header now shows **Max hit**, **Attacks
with** and **Type**.

## 4. Gear picker: measured, not guessed

`calculateItemScore()` ranks items by stat bonuses plus ~30 name checks. That's
why the same three weapons came out for every boss. It's still there as the
starting point, but `generateSetup()` now finishes with `refineByMeasuredDps()`:

- for every slot, try each candidate that passes the existing filters
  (equippable, style-legal, mechanic-legal, inside budget),
- run `CombatCalculationService.calculateCombat()` on the trial setup — the same
  maths the DPS readout uses — against *this* monster's defences,
- keep the swap only if measured DPS actually goes up,
- two passes, so two-handers vs shield and bow vs ammo settle,
- then re-apply `enforceCompatibility()` and `enforceBudgetLimit()`.

So the heuristic result is the floor, never the ceiling, and nothing can get
picked that the old filters would have rejected.

### Before / after (maxed account, no budget cap, measured with your own calculator)

| Target | Style | Old build | After data fix | After DPS picking |
|---|---|---|---|---|
| King Black Dragon | Melee | 4.43 (Soulreaper axe) | 4.48 | **8.16** (Osmumten's fang) |
| Vorkath | Melee | 4.43 (Soulreaper axe) | 4.48 | **8.87** (Dragon hunter lance) |
| Vorkath | Ranged | 7.26 (Bow of faerdhinen) | 5.66 | **9.80** (Webweaver bow) |
| Zulrah | Magic | 5.18 (Harmonised staff) | 10.00 | **11.96** (Sanguinesti staff) |
| General Graardor | Melee | 4.26 (Soulreaper axe) | 4.31 | **6.44** (Osmumten's fang) |
| Abyssal demon | Ranged | 8.02 (Bow of faerdhinen) | 6.26 | **11.03** (Scorching bow) |
| Cerberus | Melee | 7.60 (Soulreaper axe) | 7.40 | **9.81** (Inquisitor's mace) |
| Alchemical Hydra | Ranged | 8.04 (Bow of faerdhinen) | 6.28 | **11.02** (Webweaver bow) |

The old build picked Soulreaper axe / Bow of faerdhinen / Harmonised staff for
every single target. It now picks per target: lance at Vorkath and Hydra (dragon),
fang at KBD and Zulrah (stab), Inquisitor's at Cerberus (crush 25 defence),
Scorching bow at demons (demonbane), rapier at abyssal demons.

Note the middle column going *down* in places — e.g. Kree'arra ranged 7.15 → 2.41.
That's not a regression, that's the old number being fiction: Kree'arra's ranged
defence was recorded as 15 instead of 200.

## 5. WikiSync lookup (new feature)

Type a RuneScape name in **Settings → WIKISYNC LOOKUP**, hit Load Profile, and
every recommendation is rebuilt for that account. "Use This Client" switches back.

It reads the public WikiSync profile the wiki's own tools use:

```
GET https://sync.runescape.wiki/runelite/player/<name>/STANDARD
```

That is the same service the WikiSync RuneLite plugin uploads to, which most
RuneLite users already run. BossWise reads two things out of it: `levels` (24
skills, keyed by display name) and `quests` (quest name to 0 = not started,
1 = in progress, 2 = finished). Diaries, music, collection log and combat
achievements are ignored for now — they are in the payload if you want them.

What it builds: a `PlayerAccount` with real levels (boosted = real, since a
lookup cannot know someone's potions), the combat level computed with RuneLite's
`Experience.getCombatLevel`, total level, finished quest names, and quest states
mapped onto the client `Quest` enum where the names match. That flows straight
into `canEquip()`, the gear optimiser, the boss finder and the progression panel —
no other code had to change.

New/changed code:

- `service/WikiSyncService.java` — the lookup. `parseProfile(String)` is a pure
  function with no network, which is what the tests hit.
- `scanner/AccountScannerService` — `clearCustomAccount()`,
  `isUsingExternalAccount()`, and `scanAccount()` now returns early while a
  looked-up account is active, so a client tick cannot overwrite it.
- `model/PlayerAccount` — added `getCompletedQuestNames()`.
- `ui/SettingsPanel` — the card. Old 3-arg constructor still works.

Notes:

- 404 from the endpoint is treated as "that player has not used WikiSync" rather
  than an error, because that is the normal case for anyone without the plugin.
- Results are cached for 5 minutes per name; the call runs on OkHttp's thread and
  the UI hops back to the Swing thread itself.
- `WikiSyncService` builds its own `OkHttpClient` on first use because
  `BossWisePluginPanel` creates `SettingsPanel` directly. If you would rather use
  RuneLite's shared client, inject `WikiSyncService` in `BossWisePlugin` and pass
  it to the 4-arg `SettingsPanel` constructor — that is the only change needed.
- Tests: `src/test/java/com/bosswise/WikiSyncServiceTest.java` (12 cases, fixture
  is the real payload shape). I ran the same 25 assertions headlessly here and
  they pass; the live HTTP call could not be exercised from this environment, so
  the one thing still unproven is the request itself.

I also ran the optimiser against looked-up accounts to check the loop end to end
(Vorkath, melee): a maxed profile gets dragon hunter lance + Torva at 9.47 dps, a
75/80/70 profile gets Zamorakian hasta + Bandos chestplate at 4.38, and a
50/55/40 profile gets granite hammer + fighter torso. Same code path, different
answers, which is the point of the field.

## 7. Requirement data is still hand-typed

`canEquip()` gates on `reqSkills`, and the wiki dataset does not carry
requirements, so the sync could not check them. Spot-checking found real errors:

- Dragon hunter lance was listed at 70 Attack; the wiki says **78** (it was
  raised from 70, so the file is stale). Fixed.
- Dual macuahuitl was listed at 75 Attack; it is **70 Attack and 75 Strength**.
  Fixed.
- Inquisitor's mace at 80 Attack checked out.

With the lance at 70, a 75-Attack account was being told to use a weapon it
cannot wield — that matters a lot more now that accounts can be loaded by name.
The other ~220 requirement entries are unverified; worth a pass of their own.

## 8. What I did NOT touch, and what to check

- `strategies.json` is untouched: text, methods, `"confidence": "VERIFIED"` and
  `lastVerified` are all as you had them. The stats are wiki-sourced now; the
  strategy prose isn't, so that VERIFIED stamp is still your call.
- **Nothing was run inside a live client.** I compiled every file I changed
  against your compiled classes, and I ran the databases, the combat calculator
  and the gear optimiser headlessly (that's where the table above comes from),
  but `./gradlew test` and an in-game load were not possible here (no RuneLite or
  JUnit jars). Run those before you ship.
- Tests to watch, because they assert gear choices that the picker now makes
  differently: `UniversalAccurateGearTest` (Vardorvis/Duke slash, Cerberus
  crush/demonbane), `GearBudgetOptimizerTest` (Calvar'ion crush),
  `MultiGearSetupEngineTest`, `UltimateExpansionTest`. The data-level assertions
  I checked still hold (Vorkath 750 hp / level 732, Sand Crab 60 hp, fire giant
  water weakness 50%).
- `generate_equipment.py` still writes the old hand-typed numbers. I put a
  warning at the top: if you re-run it, run the sync after, or re-point it at the
  wiki dataset.
- Ambiguous variant picks worth a look: Kephri is matched to the wiki's
  "Shielded" row, Dusk to "Second form", the Greater demon variants to the
  level-matched rows. `wikiName` on each variant says which row it used.
- Performance: the refinement is a few hundred `calculateCombat()` calls per
  setup (plain arithmetic, no I/O). Fine on a click, but if "all viable setups"
  ever feels slow, that's where the time went.
